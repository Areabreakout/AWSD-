# AWSD+++

把安卓手机投到电脑屏幕上，用真实的键盘鼠标玩手机游戏。

## 一句话原理

电脑通过 adb 连接手机，把手机画面实时拉到一个 PyQt5 窗口里显示，同时把你的键鼠动作转换成安卓触控事件发回去。和电脑上装一个安卓模拟器效果类似，只是画面来自你手里那台真机。

## 它为什么比别的工具好用

同类工具要么用全局钩子抓键鼠（容易漏键、被反作弊杀），要么用鼠标相对滑动模拟视角（桌面光标有边界、加速度失真）。AWSD+++ 的三件事做得不一样：

1. 鼠标视角用 Windows Raw Input，直接读硬件位移，绕过系统加速，光标锁在窗口里无限转
2. 游戏模式下光标完全锁定在渲染层，不依赖全局钩子
3. 视频流每帧都做质量检查，后台回来变绿屏的情况会自动重连恢复

## 代码怎么走

```
启动.bat
  └─ launcher.py          （检测依赖，进主程序）
      └─ main.py          （窗口界面 + 视频渲染 + 悬浮按键）
          ├─ scrcpy_client.py   （视频流解析 + H.264 解码）
          ├─ adb_manager.py     （设备连接 + scrcpy-server 推送）
          └─ input_mapper.py    （键鼠 → 触控映射核心）
              └─ profiles.py    （每个游戏一份配置 JSON）
```

最重要的三个文件：

**main.py** —— 窗口长什么样、视频怎么画上去、悬浮按键怎么拖动保存，都在这里。VideoLabel 是视频渲染控件，也是游戏模式下鼠标捕获的目标。

**scrcpy_client.py** —— 和手机上跑的 scrcpy-server 说话。手机端用 MediaCodec 硬编码 H.264，这里 OpenCV 解码成一帧帧画面交给 main.py 画。同时负责把触控指令打包发回去。

**input_mapper.py** —— 把键盘 WASD 变成摇杆指令、把鼠标移动变成视角滑动、把任意按键映射成屏幕上虚拟按钮的点按。游戏模式的鼠标捕获也从这里发起。

## 先跑起来

```bash
pip install PyQt5 numpy opencv-python pillow
```

adb 要在 PATH 里（装 Android platform-tools 就行）。手机开 USB 调试，数据线插电脑，双击 `启动.bat`。

## 摇杆是怎么动的

60Hz 循环线程：

1. 看当前 WASD 哪个键按着
2. 合成方向向量（同时按两个方向会斜向走，单位化避免对角线更快）
3. 按 `JOYSTICK_RADIUS` 映射成手机屏幕坐标
4. 手机端注入 ACTION_MOVE 事件

X/Y 轴半径独立，因为手游摇杆的 Y 轴触发范围通常比 X 大。

## 视角为什么不会漂

Windows Raw Input 给的是硬件原始位移（`MOUSE_MOVE`），没有系统指针加速，和桌面上鼠标跳速无关。每帧读完位移后 `QCursor.setPos` 把光标重置回窗口中心，下一个 16ms 周期继续读数，所以鼠标可以无限往一个方向晃。

## 配置怎么存

`profiles/` 文件夹里每个 JSON 是一套游戏配置，记录按键位置、摇杆中心、视角中心。下拉框选一个就热加载进程序，不用重启。

## 已知坑

- 数据线不能是仅充电的（四线雷电/编织短线），插上手机必须弹"文件传输"才合格
- 鸿蒙 NEXT 不支持，那套协议栈和 adb 不一样
- 部分游戏反作弊可能查触控注入，自己判断
- 有些鼠标不支持 Raw Input 实测经常被卡
- 帧率最好情况只能跑60FPS 适合元神光遇
